v3.3.3 Semantic Repository Graph

Right now you have:

Function
↓

File

I would change it to:

Project

├── Files

├── Classes

│     ├── Methods

│     └── Variables

├── Functions

├── Imports

├── Dependencies

├── Call Graph

├── Inheritance

├── TODOs

├── Tests

└── Documentation

Instead of just indexing symbols, Buster would build relationships.

Then Repository Intelligence becomes capable of things like

Who calls VisionEngine.start()?

Which classes inherit Agent?

Show unused imports.

Show circular imports.

Which modules depend on OpenRouter?

Find dead code.

Generate project documentation.

Which files import cv2?

Which methods are never called?

Show dependency tree.

Export project map.

That's a massive leap in usefulness.
